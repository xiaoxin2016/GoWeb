# 登录鉴权与会话

GoWeb 使用**邮箱验证码**登录，登录后的身份由**服务端内存中的会话表**维持。
本文说明会话的工作方式、升级与灰度发版时如何保持登录状态，以及相关的安全约束。

## 登录流程

1. 用户输入邮箱（配置了默认邮箱域名时可只填邮箱名），服务端严格校验格式后
   发送 6 位验证码；验证码 10 分钟有效、一次性，同一邮箱 1 分钟内不能重发，
   单个验证码最多尝试 5 次
2. 校验通过后，服务端生成一个会话：随机 256 位令牌（base64url 编码，43 个字符）
   → 邮箱 + 到期时间，存入内存中的会话表
3. 浏览器只拿到这串令牌（Cookie `goweb_session`，`HttpOnly` + `SameSite=Lax`），
   其中不含任何身份信息，之后每个请求凭它在会话表中查出当前用户

会话有效期由控制台「登录权限 → 会话有效期」决定（默认 168 小时），从登录时刻算起。

## 会话何时失效

| 情况 | 结果 |
|---|---|
| 到达有效期 | 失效，需要重新登录 |
| 用户点击「退出」 | **服务端立即删除该会话**，即使令牌被他人拿到也无法再用 |
| 用户被移出允许名单 | 立即无法访问（每个请求都会重新核对允许名单） |
| 服务**优雅退出**后重启（升级、`systemctl restart`、`docker stop`） | **保持登录**，见下文 |
| 进程被 `kill -9`、崩溃、断电 | 所有用户需要重新登录 |

> v1.7.1 及以前的版本使用 HMAC 签名的无状态令牌，退出登录只能清掉浏览器 Cookie，
> 令牌本身到期前一直有效。现在的会话表可以在服务端真正作废会话。

## 升级与灰度发版：会话快照

会话平时只存在内存里。进程收到 **SIGTERM / SIGINT** 时按以下顺序优雅退出：

1. 停止接收新请求
2. 等待在途请求收尾，最多 5 秒（大文件上传/下载届时会被中断）
3. 把仍然有效的会话写入数据目录下的隐藏文件 **`.session`**（权限 `0600`）
4. 退出

快照是固定的隐藏文件，不做成配置项：它不是给人读写的，只是进程自己在重启之间传递状态。
放在数据目录而不是程序目录，是因为 systemd 服务启用了 `ProtectSystem=strict`，只有数据目录可写。
查看时注意用 `ls -la`（普通 `ls` 不显示隐藏文件）。

下次启动时读回快照、恢复会话，并**立即删除快照文件**。日志示例：

```
收到退出信号，正在停止服务…
已保存 12 个登录会话，重启后自动恢复
已退出
已恢复 12 个登录会话（0 个已过期，跳过），保存于 2026-10-11 08:40:18
GoWeb v1.8.0 已启动，监听 :9081
```

会触发优雅退出的操作：

| 操作 | 说明 |
|---|---|
| `install.sh` 升级 | 先 `systemctl stop`，替换二进制后再启动，用户无需重新登录 |
| `systemctl stop/restart goweb-<租户名>` | systemd 默认发送 SIGTERM，最多等待 90 秒 |
| `docker stop` / `docker restart` | 默认 10 秒后强杀；有长时间传输时可用 `docker stop -t 30` |
| 前台运行时按 `Ctrl+C` | 发送 SIGINT |

### 灰度发版建议

- **单实例逐个升级（推荐）**：多租户部署中每个租户一个实例，按租户逐个运行
  `sudo ./install.sh --name <租户名> --port <端口>`，先挑一个租户观察，
  确认无误再升级其余租户。升级期间该租户短暂不可用（通常数秒），
  已登录用户不受影响
- **同一租户同时运行新旧两个进程**（例如 Nginx 按比例分流）：会话只存在于
  各自进程的内存中，**不会在进程之间共享**。需要在 Nginx 上做会话保持
  （如 `ip_hash`），否则用户会在两个进程之间来回跳转时被要求重新登录
- 灰度结束、停掉旧进程时，旧进程保存的快照会被**下一次启动的进程**读取；
  若新进程已在运行，请删除旧进程留下的 `.session`，避免日后误恢复

### 快照的安全约束

快照中的令牌等同于登录凭据，因此：

- **只在停止期间存在**：启动读回后立即删除，正常运行时磁盘上没有它
- **只在优雅退出时写**：`kill -9` 不会留下快照；也就不会因为一份旧快照
  把早已退出登录的会话恢复回来
- **不可信就整份丢弃**（一个会话都不恢复，并删除文件、记录日志）：
  - 权限不是 `0600`（组或其他用户有任何权限）
  - 不是普通文件（如符号链接）
  - 内容不是合法 JSON（写到一半被打断）
  - 任一令牌格式不对、邮箱不合规
  - 任一会话的到期时间超出当前的「会话有效期」上限——防止有人改文件给自己续出一个长期身份
- **不续命**：恢复的会话沿用原到期时间，频繁重启不会延长登录状态
- 已过期的会话直接跳过，不算异常

被丢弃时的日志：

```
会话快照 /opt/goweb-tenant-a/data/.session 不可用，已丢弃，所有用户需要重新登录: 快照权限为 0644（应为 0600）
```

## 从 v1.8.0 升级

v1.8.0 曾把快照保存为非隐藏的 `sessions.json`。新版本启动时会删除该文件（其中含有效的登录令牌），
且不从中恢复会话，因此从 v1.8.0 升级时用户需要重新登录一次。

## 从 v1.7.1 及以前版本升级

- 升级后**所有用户需要重新登录一次**（旧版的签名令牌不再被接受），此后升级不再掉线
- 数据目录中的 `secret` 文件（旧版的会话签名密钥）已不再使用，可以删除
- 回滚到 v1.7.1 及以前版本时，请先删除数据目录中的 `.session`（如果存在）：
  旧版本不认识这个文件，它会一直留到下次升级时才被读取
